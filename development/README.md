# إدارة الطلاب — بيئة التطوير

هذا مجلد **تجريبي مستقل** مخصص لتطوير قسم إدارة الطلاب قبل دمجه مع تطبيق «مواعيدي».

## ما تم إنجازه

- أُنشئ فرع `development` انطلاقًا من `main`.
- صفحة `student-registry.html` تعرض نموذج RTL متوافقًا مع الهوية الحالية لمواعيدي (Cairo / #234B6E / #A78352).
- توجد 17 خانة من سجل الطلاب، والبحث الشامل، وفلاتر للحالة والمستوى ونوع الدراسة، وبطاقات إحصائية، وعمليات إضافة/تعديل/عرض/حذف.
- جميع الأسماء **افتراضية**، والبيانات محفوظة محليًا في متصفح جهاز التجربة فقط باستخدام `localStorage`.
- لا تحتوي صفحة النموذج على مفاتيح Supabase أو الاتصال بقاعدة بيانات حية؛ لا تستخدمها لإدخال بيانات فعلية.

## المعاينة المحلية (Windows)

1. افتح المستودع على فرع `development` في VS Code.
2. افتح `development/student-registry.html` في المتصفح (أو استخدم Live Server إن كان مثبتًا).
3. جرّب إضافة طالب وهمي، واختبر البحث والفلاتر، ثم استعد الأمثلة من الزر المخصص.

إذا كان المجلد مفتوحًا على فرع `main` فلا تجرِ التجربة هناك. فرع `development` منفصل عن النسخة المنشورة.

## قواعد الأمان والنشر

- **ممنوع** تعديل فرع `main` أو ملفات النشر أثناء التطوير دون موافقة صاحب المشروع.
- GitHub Pages الحالي يُنشر من `main` بحسب إعداد المشروع الموثق في README، ويجب التحقق من إعداد Pages مجددًا قبل أي عملية دمج.
- **لا تتصل صفحة الاختبار بقاعدة بيانات الإنتاج.**
- قبل بدء مرحلة الحفظ السحابي: تجهيز مشروع Supabase **تجريبي منفصل** مع جداول الطلاب وصلاحيات RLS المقيّدة بـ `auth.uid()`، ثم إجراء اختبارات صلاحيات لحسابين منفصلين على الأقل.
- قبل الدمج النهائي: مراجعة التصميم على الكمبيوتر والهاتف، وتجربة كل العمليات، واختبار عدم تأثير قسم الطلاب في المواعيد والحسابات المالية، وتجهيز طريقة رجوع.

## الخطوة التالية

تصميم مخطط بيانات الطلاب والعلاقات مع المواعيد والاتفاقات المالية، ثم تطبيقه في Supabase تجريبي بعد اعتماده. بعد التأكد من نجاح الاختبارات، تُدمج واجهة الطلاب في التنقل الحالي للموقع ضمن فرع التطوير أولًا.

**ملاحظة:** هذا ملف للتوثيق والتجربة، وليس إعلانًا بأن قاعدة البيانات التجريبية أو الربط السحابي اكتمل.
