# Encrypted backup format v1

This is an optional browser-side encrypted wrapper around the existing full ZIP snapshot; it does not expand the data included in that snapshot. Extension `.mwb`, 37-byte header: ASCII MAWAEIDI (8), version 1 (1), random PBKDF2 salt (16), random GCM IV (12). PBKDF2-HMAC-SHA256 600000 iterations derives a non-exportable AES-256 key; AES-GCM uses 128-bit tag and authenticates the entire header as AAD. Exact UTF-8 passphrase, no normalization. New passwords require 12+ characters (recommend a long random passphrase). No password or key is sent to the server or persisted by application code. Maximum plaintext 256 MiB, plus 53 bytes envelope overhead. Whole archive processed in memory; large files on mobile may exceed device memory. Wrong password/tamper fail closed; no ZIP fallback on encryption error. Old ZIP/JSON supported. Restore creates a separate encrypted safety archive and requires explicit confirmation of saving before merge. Existing restore is a multi-stage merge, not an atomic transaction. User must keep passphrase separately; no recovery. Browser tests and physical Android/iOS testing remain necessary. Native Android port pending. Legacy archives already downloaded remain unencrypted. No database changes.
